# 调查与证据采集

## 1. 先建立地图，再沿工作流探索

确认用户给的是产品名称、网址、截图还是已安装程序。名称有歧义时核对厂商/平台；不能因为名字相近就研究另一个产品。已有用户描述先登记，再补缺，不要求用户重复提供。

建立页面/功能索引：官网帮助与教程、功能与档位表、版本说明、FAQ、导入导出/兼容性说明、可见菜单和设置。记录原始功能名便于追溯，同时给本产品独立设计的功能命名。

搜索示例：`产品名 官方 帮助`、`产品名 功能 对比`、`产品名 操作 教程`、`产品名 错误 保存 导出`。优先检索具体功能的二级页面；价格、版本与平台信息使用时重新核实。第三方教程标明其来源，不覆盖更强的当前版本证据。

形成“来源入口 → 具体功能页 → 本地可见入口 → 操作链 → 记录”的调查路线。观察主流程后按风险补边界，避免大量无目的点击。

## 2. 证据性质

| 标签 | 说明 | 可以支持什么 |
| --- | --- | --- |
| O：目标实测 | 本轮或已有可追溯记录中，实际对目标版本执行操作 | 该版本/环境下实际结果，不能外推全部环境 |
| U：用户操作报告 | 用户明确描述自己执行过的操作 | 规格来源；保留用户原意，不冒充本轮自动化验收 |
| S：截图可见事实 | 截图确实展示的入口、文本、布局或选中状态 | 可见状态；不证明点击后结果和成功链路 |
| W：网页陈述 | 帮助、FAQ、档位表或教程描述 | 公开宣称和功能线索；不等于当前账号实测 |
| H：待验假设 | 来自知识、类似产品或可见功能的推断，尚未采用 | 探索问题；不作为已观察结论 |
| D：自主设计 | 为本产品明确采用的推断/创新方案 | 本产品合同和测试预期；不声称来自目标实测 |

一项功能可有多种来源。遇到冲突，保留版本/环境和各方结果，调查是否由平台、账号、权限或状态导致；不静默删除不合预期的证据。

## 3. 实机操作记录要点

先验证目标应用与版本、桌面是否可交互、窗口身份与来源材料是否匹配。按已安装工具的实际说明操作，不沿用旧版工具名称、签名或坐标。无法操作时写明原因和需要的协助。

每条关键操作记录：

- **前置**：文档/项目、所选对象、设置、权限、设备、账号档位和初始状态。
- **输入**：文本、参数、测试文件；鼠标/快捷键/菜单的操作顺序。
- **UI**：入口、控件含义、焦点/选择、禁用条件、加载/进度、反馈文字。
- **状态**：操作前后状态、处理中/取消/失败/完成、持久化范围。
- **输出**：文件、画面、声音或对象结构；确认输出真实可用。
- **异常**：完整可见错误、触发条件、恢复办法、原数据是否保留。
- **证据**：日期、目标版本、环境、来源编号及截图/录制/日志路径。

截图保留必要上下文；只拍主窗口不能证明后台输出成功。若裁切或脱敏，保留原图并说明处理，不把重绘界面作为实测证据。

## 4. 有针对性的探索维度

按产品特性选取，非每个产品强制执行全部组合：

| 维度 | 示例问题 |
| --- | --- |
| 主流程 | 从新建/输入到保存/导出/重新打开能否闭环？ |
| 选择与输入 | 未选择、多选、空文本、中文输入、长文本、非法参数如何表现？ |
| 状态与开关 | 功能启用后能否关闭？重开窗口/重启后状态如何？ |
| 历史与引用 | 撤销/重做、删除引用对象、取消编辑后是否一致？ |
| 文件与持久化 | 重名、格式不符、权限失败、保存失败、刷新或重启后的数据如何？ |
| 布局与显示 | 不同窗口尺寸、缩放、滚动、遮挡、焦点是否影响操作？ |
| 任务生命周期 | 空闲、处理中、取消、完成、错误能否正确转移与恢复？ |
| 依赖与冲突 | 哪些功能必须先开启设备/权限？并发任务、快捷键冲突如何提示？ |

只用可恢复的测试数据探索失败路径，不对真实文档做破坏性实验。不因要“尽可能完整”而擅自购买会员、创建账号、安装工具、开启设备或发送真实直播。

## 5. 收敛调查

将所有发现映射进完整候选清单，标出已有证据、未知、是否纳入及依赖。主要操作链和高风险状态已能描述后，转入规格与决策；重要缺口补测，普通缺口可在授权范围内形成 D 类设计。

不要用“无法看到会员功能”推定该功能不存在或决定本产品不开发；保留 W/S 类线索，并让用户决定本产品范围。不要把演示站、模拟设备或自己的替代产品当成原目标实测。
